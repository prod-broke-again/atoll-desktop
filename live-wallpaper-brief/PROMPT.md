# Задача: собственный движок живых обоев для Windows

Ты senior-инженер, который строит этот проект с нуля и доводит до состояния, в котором его не стыдно выложить на GitHub. Работаешь на машине пользователя (Windows 11), можешь запускать, собирать и тестировать.

Результат: фоновое приложение, которое рисует интерактивные обои **позади иконок рабочего стола**: коллаж из пинов пользователя с плавной сменой, живая погода, часы, графики CPU/RAM/GPU, авто-пауза в играх.

## 0. Принятые решения (не пересматривать без веской причины)

**Стек: C# (.NET, актуальная LTS) + WebView2 + TypeScript.**

- **Host на C#:** окно, встраивание в рабочий стол, хуки, телеметрия, погода, файловая система, конфиг, трей, автозапуск.
- **Frontend на TypeScript (strict) + Vite:** вся графика и виджеты. Canvas 2D / WebGL (PixiJS допустим), без тяжёлых UI-фреймворков.
- **Почему не Python:** встраивание WebView2 в WorkerW из Python хрупкое, упаковка и память хуже, нет нормальной типизации Win32. Python не использовать.
- **Почему не Rust/Tauri:** тоже рабочий вариант, но выше цена итераций. Если в ходе spike (этап M0) выяснится, что C# + WebView2 не справляется, остановись и объясни, не переходи молча.

Решения оформляй как короткие ADR в `docs/adr/`.

## 1. Как устроен рабочий стол (проверь сам, не верь слепо этому тексту)

- Окно рабочего стола состоит из слоёв: `Progman`, `WorkerW`, `SHELLDLL_DefView` (иконки). Классический трюк: отправить `Progman` недокументированное сообщение `0x052C`, найти нужный `WorkerW` и сделать своё окно его дочерним (`SetParent`).
- **В Windows 11 24H2 и новее иерархия окон изменилась.** Многие гайды устарели. Реализуй определение слоя так, чтобы работали оба варианта (Win10/Win11 ранние сборки и 24H2+), с логированием того, что найдено.
- Окно за иконками **не получает мышь**. Нужен low-level mouse hook (`WH_MOUSE_LL`) или Raw Input. События пересылаются в страницу, только когда курсор находится над пустым рабочим столом (не над чужими окнами). Частоту ограничивай.
- Обработай: несколько мониторов с разным DPI (Per-Monitor V2), смену разрешения и горячее подключение мониторов, перезапуск `explorer.exe` (сообщение `TaskbarCreated`: переприкрепиться), сон/пробуждение, блокировку сессии.
- При штатном и аварийном завершении не оставлять «чёрный экран»: корректно снимать окно и обновлять обои системы.

## 2. Функциональность

1. **Коллаж из пинов.** Источник: папка `%USERPROFILE%\Pictures\Pins` (настраиваемая), `FileSystemWatcher` с debounce. Стили раскладки: `diagonal`, `bento`, `hex`, `fan` (+ задел под новые, стиль = отдельный модуль). Смена подборки по таймеру с красивым переходом (кроссфейд / каскад по плиткам / сдвиг). Подбор изображений по цветовой гармонии: см. раздел 5.
2. **Погода.** Open-Meteo (без ключа). Запросы делает host, не страница: кеш, таймауты, экспоненциальный backoff, работа без сети. Город выбирается в настройках (геокодинг Open-Meteo), по умолчанию виджет скрыт, пока город не задан. Ничего персонального в коде не хардкодить.
3. **Часы и дата.**
4. **Система:** CPU, RAM, сеть, GPU (загрузка, по возможности температура). Для GPU предпочти PDH-счётчики «GPU Engine» (не требуют админа). `LibreHardwareMonitorLib` только как необязательный источник за интерфейсом. Данные идут в страницу через `PostWebMessage` (JSON с версионируемой схемой), не через сокеты.
5. **Авто-пауза.** Условия: полноэкранное приложение/игра (`SHQueryUserNotificationState` + сравнение foreground-окна с прямоугольником монитора), режим экономии батареи, блокировка сессии, выключенный монитор, пользовательский список процессов. Пауза = остановка `requestAnimationFrame`, остановка телеметрии, `TrySuspend` у WebView2. Цель: около 0% CPU/GPU в паузе. Возобновление без рывков.
6. **Трей и настройки:** иконка в трее (пауза, смена подборки сейчас, настройки, выход), отдельное окно настроек (второй WebView2, обычное окно). Настройки применяются без перезапуска.
7. **Автозапуск** (Task Scheduler или ключ Run, обоснуй выбор), **single instance** (mutex), чистое завершение.

## 3. Архитектура и качество кода (обязательно, уровень senior+)

**Host (C#)**
- Слои: `Native` (интероп) → `Core` (чистая логика без зависимостей от Windows и UI) → `Services` → `App/Host`. Зависимости направлены только вниз.
- `Microsoft.Extensions.Hosting`: DI, конфигурация, логирование. Никаких синглтонов через статические поля и service locator.
- Win32 только через **CsWin32** (source generator), без ручных `DllImport`-сигнатур. Все `HWND`, хуки и COM-объекты в `SafeHandle`/`IDisposable`, с детерминированным освобождением.
- `Nullable` включён, `TreatWarningsAsErrors`, анализаторы (`Microsoft.CodeAnalysis.NetAnalyzers`, Roslynator или аналог), `.editorconfig`, `Directory.Build.props`, central package management.
- Асинхронность: `CancellationToken` везде, без `async void` (кроме обработчиков событий), без `.Result`/`.Wait()`, UI-поток никогда не блокируется. Хук мыши живёт в своём потоке с message loop и не делает тяжёлой работы.
- Ошибки: без пустых `catch`; различай ожидаемые (сеть, файл занят) и баги. Глобальный обработчик необработанных исключений пишет в лог и пытается восстановиться.
- Логи: `Microsoft.Extensions.Logging` + Serilog (rolling file в `%LOCALAPPDATA%`), структурированные, уровни осмысленны.
- Конфиг: JSON в `%APPDATA%`, **версия схемы и миграции**, валидация при загрузке, атомарная запись (temp-файл + replace), понятные ошибки вместо падения.
- Алгоритмы (анализ цвета, подбор, история, математика раскладок) пиши как чистые функции/классы в `Core`, чтобы их можно было тестировать без Windows.

**Frontend (TypeScript)**
- `strict: true`, ESLint + Prettier, без `any`.
- Виджет = модуль с единым контрактом: `manifest`, `mount`, `update(data)`, `pause`, `resume`, `destroy`. Реестр виджетов, раскладка из конфига, валидация конфига (zod или JSON Schema).
- Стили раскладки — тоже модули с одним интерфейсом (`layout(viewport, count) -> slots`, `render`).
- Дизайн-токены (цвета, отступы, шрифты) в одном месте, тёмная тема по умолчанию. Анимации плавные, с ограничением FPS (настройка, по умолчанию 30 в простое и 60 во время переходов).
- Контракт сообщений host ↔ page описан типами и общей JSON-схемой, с проверкой на обеих сторонах.

**Безопасность WebView2:** страница грузится только с виртуального хоста (`SetVirtualHostNameToFolderMapping`), не `file://`; навигация наружу запрещена; DevTools, контекстное меню и горячие клавиши браузера отключены в Release; строгий CSP. Картинки пинов отдаются через отдельный виртуальный хост, только чтение.

**Производительность (измерять, а не предполагать)**
- Картинки не грузить в полном размере: host делает кеш миниатюр (JPEG/WebP под размер плитки с учётом DPI), декодирование не на UI-потоке.
- Бюджеты: простой ≤ 2% CPU и разумная GPU-нагрузка на средней машине; в паузе около 0%; утечек памяти за сутки работы нет. Добавь режим диагностики (FPS, память, время кадра) и приложи результаты измерений в `docs/perf.md`.

**Тесты и процесс**
- xUnit + FluentAssertions для `Core` (анализ цвета, группировка по оттенкам, подбор без повторов, миграции конфига, математика раскладок). Vitest для TS-логики раскладок и валидации.
- Интеграционный smoke-тест, где возможно (запуск host, handshake со страницей).
- GitHub Actions: build, test, lint, format-check для C# и TS.
- Git: небольшие осмысленные коммиты (Conventional Commits), ветки по этапам.
- Документация: `README` (по-русски: что это, скриншоты, установка, настройка), `docs/architecture.md` с диаграммой (Mermaid), ADR, `CONTRIBUTING`-минимум. Код, идентификаторы, комментарии и коммиты на английском.
- Публикация: self-contained single-file x64 (`dotnet publish`), проверка, что WebView2 Runtime отсутствует/устарел, обрабатывается с понятным сообщением. Инсталлятор (Inno Setup или MSIX) как последний, необязательный этап.

## 5. Референсы (лежат в папке `reference/`)

- `reference/pins_wallpaper.py`: рабочий прототип. Перенеси идеи, не переписывай построчно: K-Means по уменьшенной картинке (80×80, 3 доминантных цвета), классификация в hue-группы, подбор «основная группа + соседние оттенки», сортировка по тону для градиента, история последних подборок против повторов, тёмный фон из средних цветов подборки. В C# используй SkiaSharp или ImageSharp; K-Means пиши сам (маленький, тестируемый класс), без тяжёлого ML-пакета.
- `reference/collage_styles.html`: рабочие реализации раскладок `diagonal`, `bento`, `hex`, `fan` на Canvas 2D (математика плиток, углы, скругления, тени). Возьми её за образец внешнего вида и перенеси в стили-модули на TypeScript, улучшив: анимированные переходы, работа с DPI.

## 6. Чего не делать

- Не копировать код Wallpaper Engine или Lively (у Lively лицензия GPL). Изучать подходы можно, код нет.
- Не хардкодить пути, город, имя пользователя, ключи.
- Не вызывать внешние сервисы со страницы. Всё сетевое через host.
- Не оставлять TODO без записи в `docs/backlog.md`. Не оставлять закомментированный код.
- Не объявлять этап готовым без реального запуска. Если что-то нельзя проверить на этой машине (например, вторая видеокарта или другая сборка Windows), напиши об этом явно в отчёте.
